# Shared Reader integration

Apply this contract when preparing another paper for the existing MatterSyn atlas. Reuse the accepted source review and inspect changed claims independently; a new presentation does not require repeating unchanged source work.

- Start from the current canonical schema and a named source commit. Return additive records, assets and shared-JSON deltas. Do not return whole shared registries or a separate demonstration website that the integration owner must reconstruct.
- Include the immutable Reader presentation additions, material-hub method membership, source/figure associations, stock and solution displays, chemical bindings and stage illustrations. A canonical JSON file alone is not an integrated Reader contribution. Observation rows and supporting procedures stay distinct from growth routes.
- Compute binding hashes from the final canonical bytes, after review-status metadata is settled. Every record needs its chemical-binding entry and source digest, including an empty material map for records without reagents. Refresh per-material notes, solution-context digests and Reader-input digests together. Keep reusable molecular geometry separate from paper-specific experimental context.
- Package selected figures with source PDF/page, crop bounds or embedded-image provenance, exact hashes, and supported sample scopes. Visually inspect every crop boundary and caption. Complete page renders and long Methods text-column crops remain private even when the crop filename calls them a figure. Preserve their extracted facts and locators without publishing the source-text image. Do not enlarge a low-resolution image and describe the interpolation as additional evidence.
- Retain source-defined condition variants and table rows. Join tables only through verified source identifiers; differing row counts or ordering are not a crosswalk. Repeated settings do not establish distinct physical batches. Keep reported phase, size and property scope separate from exact atomistic-coordinate eligibility.
- Extend the shared apparatus renderer where its heating, vacuum, injection, separation or washing components fit. Keep source conditions alongside the scene. New source-specific graphics should fill a real representation gap, not replace the established presentation with generic icons.
- Update cache versions along imports of changed modules. Check a fresh public page after deployment and distinguish a stale browser tab from a confirmed deployed-code error. An HTTP200 response alone does not show that the interactive Reader rendered correctly.
- Stage downloadable tables only inside the current paper's generated data directory. Reject absolute, parent-traversal and cross-paper paths. Keep detailed audits, full text and private archive paths out of the public package; safe audit summaries and content hashes preserve the review history.

The integration owner verifies that old scientific records and eligibility remain unchanged, checks the new bindings and Reader controls, and batches independently accepted contributions for publication. Count a new paper only after successful deployment and anonymous verification. Keep inherited source work, new extraction, independent audit, integration, publication and rework as separate measurements. A targeted correction receipt should identify its precise scope instead of claiming another full-document audit.

Reader quantity values must retain the canonical unit, approximation and bound (for example ≈10 nm or >95%). Do not project only a numeric value or a null bound into a text-only fact renderer. Keep source-defined experimental-table rows separate from full routes and imported benchmark rows in inventory totals. Check every public context link against staged files, including compact table indexes.

Sidecars must not name an undelivered source file. Declare every public protocol-stage CSV in the reviewed table registry as well as in its sidecar, and verify the delivered hash. Protocol stages are not additional recipes. When a condition is stated in a general Methods paragraph, cite that paragraph separately from the step that inherits it; do not label it an unsupported assumption or imply that the step repeats it.

Validate the browser-facing record view before freezing a package. The current Reader consumes each record's `figures` array of complete figure objects; a populated `figures_by_source` map or a list of string IDs does not supply the gallery. Include a visible `scopeLabel`, source pointer, supported product contexts, data links and reviewed intuition where available. Use the current rendered contribution as the contract, not a schema-only approximation. The metadata builder rejects missing figure arrays and scope labels; an explicit empty array is valid when no figure is assigned. Keep the review's `paper_id`, canonical primary source group and formal review filename joined explicitly, while retaining separate main/SI source IDs.

Crop coordinates must state their convention (XYWH versus XYXY). Verify the actual selected pixels against the source render, and visually inspect the bottom-most axis label on every spectrum; a shared rectangle across several pages may clip one panel. Keep precursor spectra separate from final-nanocrystal characterization. Apparatus drawings are conceptual and must not imply an unreported quantitative liquid level, pressure or geometry. Check enlargement controls against the actual element type: an image-backed SVG requires image support in a modal designed originally for inline SVG.

After final review-status edits, bind all dependent hashes, including the publication asset registry's record-provenance entries. If two delivery paths intentionally use identical image bytes, retain both paths under that asset hash rather than losing one in a duplicate-hash lookup. Record status-only hash corrections separately from scientific changes and new-paper throughput.

Verify that every assigned figure category reaches a visible gallery: composition evidence such as XPS belongs in the characterization gallery without becoming an atomic-structure training label. Test long phase and morphology descriptions at desktop and mobile widths; global definition-list rules must not compress labels or center long source qualifiers. Run figure-integrity tests on the documented prebuild-transformed projection, since the raw checkout intentionally retains a different private/public artifact mapping.
