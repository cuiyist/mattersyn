# Owner storage instruction, October 8, 2026

Use GitHub as the durable home for reviewed code, records, citations, memory, skills and safe audit summaries. Push these through the normal reviewed source transaction. Do not retain additional Desktop exports of files already durably stored in the source or site repositories.

Keep only the necessary source and site working checkouts. Temporary source projections, full website builds and transport copies are working artifacts, not archival evidence. Retain their small source pins, manifests, checksums, scientific acceptance receipts, CI results and publication receipts. Remove obsolete generated payloads after confirming their reconstruction source and checking the exact deletion scope. Preserve the current pending candidate until it is released, explicitly abandoned or reconstructed under an accepted handoff.

Do not create a new complete source copy for each correction, auditor or trial. Use Git objects and compact disjoint patches for unchanged baseline content; reuse the same bounded active staging area. Remove superseded payloads at substantive checkpoints instead of accumulating them under new revision names. Before a job creates another full build, measure existing staging usage and retire an obsolete verified copy. Aim to keep generated staging within 10 GiB; if an active release temporarily needs more, record why and remove it when the release closes. This is a storage budget, never a reason to weaken a gate or delete unique evidence.

Preserve owner-created folders and original papers/SI. Full text/OCR, full-page renders, raw source quotations, credentials, detailed private audits and unreviewed scientific drafts must not enter the public repositories. Keep only private material still needed for the current work, scientific traceability or an unresolved correction; do not replicate it into multiple working trees. Disposable text/renders can be regenerated from retained source documents, but removal requires verified source identity and preservation of the small audit receipts.

The owner separately authorized a local model. Its weights and the necessary offline runtime remain local; inference sends no paper text elsewhere. Do not put model weights or enormous caches into GitHub. GitHub's ordinary repository file-size limit is 100 MiB per file, and repositories are not a backup service for large working caches. See [GitHub's file guidance](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

For cleanup, resolve each absolute target within the explicitly approved workspace; reject reparse points and unverified paths. Check live users and exact reconstruction/file evidence before removal. Preserve original-paper directories and all unique or mismatched files. Use one native filesystem shell end to end, with literal paths. Record actual removed bytes, files and remaining disk space; historical manifest estimates are not reclaimed-space measurements.

No local working copy is claimed to be a GitHub backup until the relevant remote commit is verified. Do not upload private evidence merely to satisfy a storage target. Disk cleanup is authorized during the quality hold; it does not authorize new curation or publication.
